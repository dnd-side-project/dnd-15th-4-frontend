# 📝 07. 커밋 메시지 컨벤션

명확한 이력 추적을 위한 Git 커밋 메시지 규칙입니다.

## 📌 핵심 원칙

- **1 Commit = 1 Issue/Problem**: 하나의 커밋에 너무 많은 변경사항을 담지 않습니다.
- **타입은 소문자, 본문은 한글**: 커밋 타입만 영문 소문자로 쓰고 제목/본문은 한글로 작성합니다.
- **브랜치명 기반 이슈 번호 자동 태깅**: Husky(Git hooks) 설정으로 인해 **현재 작업 중인 브랜치명에서 이슈 번호를 자동으로 추출**하여 커밋 메시지 끝에 추가합니다.

## 🌿 브랜치 네이밍 규칙

`prepare-commit-msg` 훅은 **현재 브랜치명에서 `#숫자` 패턴을 정규식으로 추출**하여 커밋 메시지 제목 끝에 붙입니다. 이슈 번호가 자동으로 태깅되게 하려면 브랜치명에 반드시 `#이슈번호`를 포함해야 합니다.

```text
type/#이슈번호-작업내용

예) feat/#22-login
```

- 브랜치명에 `#숫자` 패턴이 없으면 이슈 번호가 자동으로 추가되지 않습니다.
- 커밋 메시지에 이미 `(#숫자)`가 포함되어 있으면 중복으로 추가되지 않습니다.

## 🔀 PR Merge 전략

브랜치 흐름에 따라 아래 Merge 방식을 사용합니다.

| 브랜치 흐름           | Merge 방식       |
| :-------------------- | :--------------- |
| `feature` → `develop` | Squash and Merge |
| `develop` → `main`    | Merge Commit     |
| `hotfix` → `main`     | Merge Commit     |

- **`feature` → `develop` (Squash and Merge)**: 기능 브랜치의 여러 커밋을 develop에는 1개로 합쳐서 이력을 깔끔하게 유지합니다.
- **`develop` → `main` / `hotfix` → `main` (Merge Commit)**: develop과 main은 장기간 유지되는 브랜치이므로, 병합 지점을 이력에 명확히 남기고 두 브랜치의 커밋 이력이 서로 어긋나지 않도록 Merge Commit으로 통일합니다.

## 🏷️ 커밋 타입 목록

| 타입       | 의미                                      |
| :--------- | :---------------------------------------- |
| `feat`     | 새로운 기능 추가                          |
| `fix`      | 버그 수정                                 |
| `docs`     | 문서 수정 (README, CLAUDE.md 등)          |
| `style`    | 포맷팅, 세미콜론 등 코드 변경이 없는 경우 |
| `refactor` | 코드 리팩토링                             |
| `test`     | 테스트 코드 추가 및 수정                  |
| `chore`    | 빌드 업무, 패키지 매니저, 설정 파일 수정  |
| `rename`   | 파일/폴더명 수정 또는 이동                |
| `remove`   | 파일 삭제                                 |
| `!HOTFIX`  | 긴급 치명적 버그 수정                     |

## ✍️ 작성 포맷 및 규칙

```text
type: 제목 (한글 50자 이내, 마침표 금지)

본문 내용 (선택 사항, 상세 설명 필요 시 작성)
```

### ✅ DO

```
feat: 약속 장소 도착 시간 계산 로직 추가

// 자동 변환 결과 -> feat: 약속 장소 도착 시간 계산 로직 추가 (#14)
```
